## Как выкатывать изменения

1. Тесты: `cd pirojki && DB_PATH=:memory: python3 -m unittest discover -s tests` (для `platform/` — `python3 -m unittest discover -s tests`).
2. Закоммитить и запушить в `main`.
3. Railway сам не деплоит: после пуша вызвать `connect-service-source` (repo `rozik12/yamin-baliq`, ветка `main`) для нужного сервиса. Только после завершения пуша, не параллельно.
4. Через 1–3 минуты проверить `list-deployments` (SUCCESS) и `get-logs` (строка `Run polling for bot`).
5. Не использовать `sleep` на переднем плане, только в фоне. Не делать `pkill -f` по шаблону, совпадающему с собственной командой.

Если терминал блокируется ошибкой проверки безопасности — подождать и повторить позже. Крайний случай: `mcp__github__push_files`, но только для небольших файлов (целые большие файлы пересылать дорого и рискованно).

## Бесплатный план Railway: как добавлять новых ботов без новых сервисов

Бесплатный план не даёт создавать новые сервисы и проекты (`create-service` отвечает «Free plan resource provision limit exceeded»; уже есть 3 сервиса: `bot`, `platform`, `pirojki`). Не пытаться создавать четвёртый и не просить владельца платить, пока это не нужно. Делать так:

1. **Новый клиент ресторанного бота** (меню, заказ, оплата переводом, бронь) — это папка `clients/<имя>/` с `menu.json` и `logo.jpg` (образец: `clients/shabboda/`), плюс запуск ещё одного процесса `bot.py` рядом с Yamin Baliq. Запуск делает `run_clients.py`: он стартует основной бот и, если задана переменная `SHABBODA_BOT_TOKEN`, второй процесс с `CLIENT=shabboda`, своей базой (`<том>/shabboda.db`), своими админами (`SHABBODA_ADMIN_CHAT_ID`) и своей картой (`SHABBODA_CARD_NUMBER`, `SHABBODA_CARD_HOLDER`). Карта, курьеры, Яндекс и оплата основного бота второму не передаются.
2. **Третий клиент в том же сервисе:** добавить в `run_clients.py` ещё одну запись по образцу `shabboda` (свой префикс переменных, своя база), сделать тесты в `tests/test_run_clients.py`.
3. **Клиентам попроще** (магазин, запись, заявки, поддержка, рекрутинг) новый бот не нужен: их подключают к платформе @Yeshimsuperbot (`platform/`), один бот обслуживает много бизнесов.
4. Переменные новых ботов ставить в сервисе `bot` через `set-variables` с `skipDeploys: true`, потом один раз вызвать `connect-service-source` (деплой).

Подводные камни:
- В сервисе `bot` стоит своя команда запуска `python run_clients.py`. Она перекрывает `Procfile`; если её сбросить на `python bot.py`, второй бот молча перестанет работать. Проверка: `get-service-config` (`startCommand`).
- После деплоя убедиться, что в логах есть `Run polling for bot @...` для КАЖДОГО бота сервиса (логи брать по `deploymentId`, иначе новые строки можно не увидеть).
- Один токен = один работающий бот. Тот же токен в двух местах даст ошибку `conflict`.
- Аватарку и описание бота ставить через Bot API: `setMyProfilePhoto` (квадратный jpg) и `setMyShortDescription`, токен брать из переменных Railway.
- Если владелец когда-нибудь перейдёт на платный план, можно вернуться к одному сервису на бота.

## Экономия лимитов

- Не читать большие файлы целиком, использовать `Grep` и `Read` с `offset`/`limit`.
- Не пересылать файлы целиком, если можно сделать точечную правку.
- Не создавать субагентов без необходимости.
- Проверять результат одним запросом логов, а не повторными опросами.
